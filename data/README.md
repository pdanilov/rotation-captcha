# Datasets

All angles are **clockwise degrees in `[0, 360)`**. Geometry is circular-disc: the
rotating content lives inside the inscribed circle of a square image on a white
background (Baidu-style), matching the real captchas. Solving = predict the
clockwise angle, then rotate back counter-clockwise by that amount.

## Layout

Two parallel views of the same data:

- **`data/raw/`** — flat, per-dataset source folders (one directory each), the human/tool-friendly form.
- **`data/hf/`** — the same data as HF `datasets` imagefolders with split subfolders + `metadata.csv`, the training-consumed form (see [below](#hf-datasets-layout-datahf)).

`data/raw/real_caps_*` are the committed source of truth; the COCO crop cache
(`data/raw/coco_objects/`) and everything under `data/hf/` are git-ignored and
regenerated by the scripts.

## Sources

| Set | Raw path | Count | Labeled? | Role |
|-----|------|-------|----------|------|
| COCO object crops | `data/raw/coco_objects/` | ~12k (val) | n/a (base images) | synthetic **train/val** via on-the-fly rotation |
| Real captchas (labeled) | `data/raw/real_caps_labeled/` | 200 | ✅ angle in filename | domain-gap **test** set |
| Real captchas (unlabeled) | `data/raw/real_caps_unlabeled/` | 30 | ❌ | domain adaptation / pseudo-labeling / qualitative eval |

**Why object crops, not raw images:** real rotation captchas show a single
recognizable object centred in the disc, not a wide scene. We cut each annotated
COCO object out using its bounding box — square of side `max(w, h)` centred on the
box (clamped inside the image), then resized — so the synthetic discs match that
distribution. Tiny objects (<64px) are skipped. Source: the HF
[`detection-datasets/coco`] dataset (images + boxes together, pinned revision),
loaded via `datasets.load_dataset` — no manual image/annotation downloads. Its
bboxes are `[x_min, y_min, x_max, y_max]` and it carries no `iscrowd` flag, so
crowd regions are not filtered. `crop_coco_objects.py` also writes a manifest
(`data/raw/coco_objects/manifest.csv`: filename, image_id, category) that
downstream tools read instead of any COCO annotation file.

**Ambiguous-orientation filter:** the pipeline assumes each base crop is upright
(0°). That fails for objects with no reliable canonical "up" — rotationally
symmetric ones (bowl, pizza, apple, clock, ball, …) and amorphous/variably-posed
ones (banana, teddy bear, kite, handbag, cup, …) — which would inject wrong/undefined
angle targets. Real captchas avoid such images too, so we drop them
(the moderate blocklist in `crop_coco_objects.py`, ~22% of crops). Filtering happens at crop time
via `crop_coco_objects.py --exclude-categories` (default: the moderate blocklist;
pass `none` to keep all, or a custom comma-separated list). To change the blocklist,
re-run the crop (cheap — the COCO parquet is cached). Objects that *have* an "up"
but are tilted in the source photo (banking airplane, upside-down sign) are left as
~zero-mean noise.

- Labeled real caps: 152×152, from [yixiaowang2001/rotate-captcha-solver]; filename
  `100_rot60_00_100.png` → 60° clockwise. Labels: `data/raw/real_caps_labeled/labels.csv`.
- Unlabeled real caps: 350×350, from [chencchen/RotateCaptchaBreak]; timestamp
  filenames, no angle.

## Reproducing

```bash
uv sync                                             # install all deps
uv run python scripts/fetch_real_caps.py            # -> data/raw/real_caps_{labeled,unlabeled}/ (both sources)
uv run python scripts/crop_coco_objects.py --split val --min-side 64 --max-per-category 1500
                                                    # -> data/raw/coco_objects/ (+ manifest; ambiguous cats filtered)
uv run python scripts/build_hf_dataset.py --val-frac 0.05  # -> data/hf/* (imagefolder + metadata.csv)
```

The COCO source is pulled by `datasets.load_dataset` and cached under
`~/.cache/huggingface`. Use `--split train` for ~10× more crops. Only the small
real-captcha sets under `data/raw/real_caps_*/` are committed; the COCO crop cache
and the exported `data/hf/` are git-ignored and regenerated by the scripts above.

## HF `datasets` layout (`data/hf/`)

`build_hf_dataset.py` exports split imagefolders, each with a `metadata.csv`
(`file_name` + metadata columns), loadable directly:

```python
from datasets import load_dataset

base = load_dataset("imagefolder", data_dir="data/hf/coco_objects")  # train/validation
test = load_dataset("imagefolder", data_dir="data/hf/real_caps_labeled")  # test  (angle_cw)
unlab = load_dataset("imagefolder", data_dir="data/hf/real_caps_unlabeled")  # train (no label)
```

| Dataset | Splits | Features |
|---------|--------|----------|
| `coco_objects` | train / validation | `image`, `image_id`, `category` |
| `real_caps_labeled` | test | `image`, `angle_cw` |
| `real_caps_unlabeled` | train | `image` |

The COCO train/val split is **grouped by `image_id`** (all crops from one source
photo share a split) to avoid scene/background leakage; pass `--crop-level-split`
for a per-crop split instead.
